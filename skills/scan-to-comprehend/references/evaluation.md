# Evaluate understanding

Define the reader task before evaluating the layout. Use representative readers and realistic material where possible. A before/after test should keep the facts and task comparable. A few qualitative sessions can expose failures; they do not establish a population-wide performance claim.

## Three tasks

1. **Quick scan:** after a short view appropriate to the context, ask what the page is about and which section appears relevant. Record the answer, not only the time.
2. **Targeted find:** ask for a fact, status, method, or comparison that is present. Record success, wrong answers, backtracking, and time to locate. Observe which labels or anchors were used.
3. **Explain:** ask the reader to explain the finding in their own words and identify any key caveat or source. Use a simple rubric prepared before testing: correct core fact, correct context, and no consequential misinterpretation.

Inspect mobile and desktop if both matter. For HTML, check keyboard order and accessible names. For infographics, test the text alternative or full text equivalent. Record the exact version and viewport used. If collecting actual eye-tracking data, obtain consent and use a calibrated method; a screenshot saliency model or structural CLI output is not a substitute for observed human behavior.

Report raw observations and uncertainty. “Four of five readers found the comparison row” is bounded to those readers and that task. “The design improves comprehension by 30%” requires a valid study design, defined outcome, and measured baseline.
