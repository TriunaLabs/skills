# Reader projections in the local S2C audit

`s2c_run.py` uses one saved Chromium capture for five report views. The experimental attention layer estimates visual prominence. The assistive layer uses captured accessibility-tree and Tab traversal. `s2c_reader_views.py` adds crawler, retrieval, and gap projections without a model or network call after capture. Run with `--question 'How do I start?'` to score captured passages with local BM25; without a question, retrieval uses a fixed position and length prior. The report and `reader-views.json` contain all per-node weights, chunk scores, flags, and gap callouts.

| View | Basis | Use | Limit |
| --- | --- | --- | --- |
| Crawler (`s2c-crawler-v1`) | Captured DOM roles, text, title, meta, and visible boxes | Find weak names, missing alt attributes, heading structure, and where indexable content appears | Editorial weights; no search rank or traffic prediction. Network files, JSON-LD, and full-page crawl are not checked. |
| Retrieval (`s2c-retrieval-v1`) | Heading-aware chunks after captured boilerplate is removed | Inspect which retained passages match a stated question | BM25 is local lexical matching, not an answer-engine simulation or citation prediction. |
| Assistive (`s2c-assistive-v1`) | Browser accessibility tree and observed Tab path | Review order, names, targets, and 320 px reflow candidates | Browser projection, not screen-reader speech or WCAG conformance. |
| Gap (`s2c-gap-v1`) | Element-rank differences across the above and attention | Find elements that one rule set emphasizes while another does not | The attention estimate is uncalibrated and underperformed a position-only baseline on held-out pages. Rank comparisons are not observed behavior. |

All overlays are relative to their own captured viewport. Only nodes with captured boxes can be painted, and the screenshot covers the first viewport rather than the entire page. The retrieval list can include retained text below the fold, marked by its absence from the screenshot overlay. The gap compares mapped element ranks, not pixel maps; tied weights share a percentile. For a new site or task, review the listed rules and the original captured content before acting on a suggested change. A missing alt attribute is a review candidate; an empty alt may be correct for decoration.

To replay an audit without revisiting a site, pass an existing `audit.json` and `capture/snapshot.json` to `s2c_run.py` with `--source-json`, `--snapshot`, and a new `--output` directory. The runner copies the capture images and records the chosen retrieval question in `run.json`.

## Scoring profile and saved revisions

The default versioned profile is in `scripts/s2c_scoring_profile.py`. Run `python scripts/s2c_run.py --url https://example.com/ --output audit-dir --scoring-profile my-profile.json` to apply a complete `s2c-scoring-profile/v1` JSON object. Each run writes `scoring-profile.json`, a profile fingerprint in `run.json`, the browser rule breakdown, and the reader-view scores. The local playground at `http://127.0.0.1:8787/` shows the browser and crawler weights as bars and number inputs. It also exposes passage parameters and the gap threshold. Browser weights must total 100. After a report is generated, **Apply to saved capture** creates a dated, immutable scoring revision from the saved evidence without visiting the website again. The original and earlier revisions remain available in the revision list; editing weights cannot change the captured page, rule findings, source structural-friction index, or experimental attention map.

BM25 is computed over the **retained heading and paragraph chunks of one captured page**, after hidden nodes and header, navigation, footer, and aside boilerplate are removed. Headings begin chunks; paragraphs are appended until the split target of 250 raw words would be exceeded. A single long paragraph can exceed that target. Query and chunk text are lowercased, split with Python Unicode `\w+`, and filtered by a fixed common-word list. There is no stemming, synonym expansion, embedding, external corpus, AI call, or web search. The default parameters are `k1 = 1.2` for term-frequency saturation and `b = 0.75` for chunk-length normalization. For each unique retained query term, the score adds `log(1 + (N - df + 0.5) / (df + 0.5)) × tf × (k1 + 1) / (tf + k1 × (1 - b + b × length / average_length))`, where `N`, `df`, and `average_length` are calculated from that page's chunks. The report's relative passage score divides by the highest passage score on that page. If there is no informative query term, the fallback multiplies a chunk's position prior `[1, 0.6, 0.4, 0.25]` by `min(1, raw_word_count / 80)`. If informative query terms match no chunk, all BM25 scores are zero. This is a within-page lexical comparison, not a cross-site retrieval or answer quality score.
