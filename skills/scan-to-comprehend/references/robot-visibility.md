# Robot visibility review

The phrase comparison also flags wanted information that appears only in raw source, where it may depend on an interaction to become visible, and user-supplied phrases absent from both source and the captured view. These are review candidates because wording and capture timing can explain a mismatch.

Use `python scripts/s2c_run.py --url https://example.com/page --important "Exact information visitors should find" --output audit-dir` to add `robot-visibility.json` and a **Robot visibility** report section. Up to five phrases can be supplied with repeated `--important` flags. Without them, the audit watches up to ten visible headings. This is an editorial review of whether wanted information has a robust discovery path, not a search ranking score.

The check compares normalized text and same-origin links in the initial HTML response against one Chromium DOM captured without clicks or scrolling. It screens raw robots meta and `X-Robots-Tag` for `noindex`/`nofollow`, and fetches up to 64 KB of same-origin `robots.txt` without following redirects to screen page and essential CSS/JS paths. The `robots.txt` screen uses Python's generic parser; crawler-specific interpretation requires confirmation. The report labels text or links found only after rendering as **rendering dependent**, never as proven invisible. Google can render JavaScript, although rendering and blocked resources can affect what it sees. Confirm consequential cases with the target engine's URL Inspection tool. See [Google's JavaScript SEO guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [robots.txt guidance](https://developers.google.com/search/docs/crawling-indexing/robots/intro), and [noindex guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

The `comparison` object in `robot-visibility.json` adds a bounded inventory of heading, internal-link, paragraph-text, and head-metadata differences. The report shows counts and capped evidence lists; rendered headings and links retain their captured DOM node IDs. A canonical change and headings added after render become review actions. Counts describe the captured visible state, not all content reachable through interaction. Initial HTML is saved as `source.html` with a SHA-256 digest in `run.json` so the comparison can be replayed without refetching.

To replay a captured run with the original source, use `python scripts/s2c_run.py --source-json audit.json --snapshot capture/snapshot.json --raw-html-file source.html --output new-audit-dir`. Without `--raw-html-file`, the report explicitly says detailed raw/render comparison is unavailable. The [synthetic demo](../../../examples/s2c-demo/README.md) generates a real browser report offline and contains a corrected variant for comparison.

The runner does not click tabs, open accordions, exhaust lazy loading, identify every crawler, or query an index. Content present only in a hidden panel is not automatically unindexable. A missing watched phrase may reflect wording or capture timing; inspect the underlying page before changing it. `robots.txt` controls crawling, not reliable secrecy or deindexing. The final action plan gathers this review with page basics, browser rules, and source findings.

For a prototype, use `python scripts/s2c_run.py --html-file prototype.html --output audit-dir`. The single `.html` file is rendered in a JavaScript-disabled Chromium context with external requests blocked. Inline styles and data images can render. Live URL timing, HTTP link checks, `robots.txt`, and `X-Robots-Tag` do not apply. The local playground also accepts a single file up to 2 MB, but its extracted report and screenshots stay in the local audit folder until manually removed. Do not publish that loopback server as a hosted upload endpoint. A public upload requires isolated rendering, quotas, abuse controls, retention and deletion enforcement, and policy language that matches the deployed behavior.
