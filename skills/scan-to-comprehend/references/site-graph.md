# Bounded site graph

Use this view when a one-page report raises a discovery question: can a target page be reached through ordinary links in initial HTML, and does the captured rendered home page expose a different route? The graph records the path evidence, audit date, fetch outcomes, and crawl budget. It does not simulate a person, Googlebot, or a complete website traversal.

From the repository root, run the owned synthetic example with `python examples/s2c-demo/run_demo.py`. Open the generated `site-graph.html` beside `report.html`; inspect `site-graph.json` for the exact URL sequence and fetched source digests. The demo deliberately shows a three-page initial-HTML route to `siblings.html`, a two-page route through the rendered start page, and a missing linked page. The source page's saved snapshot and raw HTML make the comparison replayable.

For a separately controlled local fixture, run `python skills/scan-to-comprehend/scripts/s2c_site_graph.py --fixture-dir examples/s2c-demo --snapshot AUDIT_DIR/capture/snapshot.json --target siblings.html --output NEW_GRAPH_DIR`. For a public site, use `--url https://example.com/ --target /desired-page --max-pages 12 --max-depth 2 --output NEW_GRAPH_DIR`; add `--snapshot` only when its desktop frame URL exactly matches the start URL. The public mode accepts HTTP(S) on ports 80/443, validates public DNS answers before each request, pins the connection to the validated IP, does not follow redirects, caps each response at 2 MB, and stops if `robots.txt` cannot be checked. It honors the generic Python robots parser for `S2C-SiteGraph/0.1`; verify crawler-specific rules separately. Keep the budgets small on sites you do not control.

The initial graph uses the first 100 raw links per fetched page and at most 50 pages or five link steps. The rendered overlay replaces **only** the start page's edges with visible links from one no-interaction desktop capture. Every subsequent step remains an initial-HTML link. A route counts as found only when its target page was fetched successfully within the budget; a linked 404 is not a reachable target. Skipped, blocked, dynamic-only pages beyond the start, interaction-revealed links, and the remaining frontier are explicit coverage gaps.

For role or task analysis, treat the shortest route as a starting hypothesis. A real task may require reading, decisions, search, forms, authentication, or links that the capture never observed. Record the user's task and test it with representative people before claiming completion or comparing conversion outcomes. A future hosted product can repeat this bounded graph across verified domains and add consented behavioral evidence, but it should preserve the distinction between structural paths and observed journeys.
