# Research track: element-level attention estimates

This is a proposed, untrained research extension for **calibrated element-level estimates**. The separate [heuristic attention baseline](attention-baseline.md) can render a relative heatmap but does **not** predict fixation probabilities, dwell, or scanpaths. Keep any future model output in a separately named evidence layer; never insert its estimates into the structural friction index or label them measured cognitive load.

## Corrected dataset premise

The public literature already pairs some gaze and structure. The [UEyes paper](https://arxiv.org/html/2402.05202) reports fixation logs, scanpaths, and per-screen JSON boxes from a detector for text, images, and faces. Verify those JSON files in the 12.9 GB [dataset archive](https://zenodo.org/records/8010312) before designing a loader; its record does not visibly state a dataset license. The [Mobile UI Saliency paper](https://userinterfaces.aalto.fi/mobile-saliency/resources/mobile-saliency.pdf) reports fixation data and manually labeled element boxes on 193 Chinese-language mobile UIs. [AGD/WebSaliency](https://arxiv.org/html/2407.02439v1) used browser DOM/CSSOM to generate component labels for its research, though the released WebSaliency assets must be checked before assuming those labels or raw scanpaths are available. [VSGUI10K](https://github.com/aalto-ui/VSGUI10K) adds visual-search trials and target cues; [WebUI](https://www.yihaopeng.tw/pdf/CHI23_WebUI.pdf) supplies a large screenshot/element corpus without gaze.

The open question is whether a **reproducible, calibrated, task-conditional element model** can transfer from those studied screens to a new page. Do not claim that no prior work joined gaze and elements or that this table would be the first such join.

## First experiment

1. **Inventory access and rights.** Record dataset version, download checksum, image rights, gaze-data rights, code license, language, viewport, viewing distance, task, and whether raw ordered fixations, element boxes, and participant IDs are actually present. Do not bundle source imagery or train a commercial model until the relevant rights are clear. A paper's license and a code repository's license do not automatically license its dataset.
2. **Start with existing paired data.** Reproduce an element-to-fixation join on the manually labeled Mobile UI Saliency set. Then inspect the reported UEyes segmentation files and reproduce the join there. Add a detector only where the dataset lacks boxes; measure detector class confusion and box overlap on held-out hand labels before attributing gaze to elements.
3. **Normalize coordinates and exposure.** Document each stimulus's displayed rectangle, scale, cropping, initial fixation cross, viewing distance, and eye-tracker accuracy. Map fixations into screenshot coordinates. Keep off-screen and unassigned fixations in explicit categories. Do not reuse a fixed 25-pixel tolerance across datasets; convert tracker uncertainty or visual-angle assumptions for each setup and run a tolerance sensitivity analysis. Resolve overlapping boxes with a documented priority rule.
4. **Separate tasks.** Fit free-viewing windows and target-cued search trials separately. A first-glance prior must not be reported as the probability of finding a task target. Treat language, UI type, device presentation, and viewport as possible transfer limits. The Mobile UI Saliency set used Chinese-language stock apps; it is a detector/join check, not direct calibration for English desktop webpages.
5. **Begin with small outcomes.** For each visible element, estimate fixation within a stated window, time to first fixation among trials where it was fixated, and dwell. Report the element's class, area, position, participant count, screen count, and uncertainty. Only add revisit and sequence rank after confirming the fixation timing and identity fields. Area and position are confounders; a large text block receiving more gaze does not establish an intrinsic text-class effect.
6. **Validate before deployment.** Split by screen or source site, not by individual fixation; keep all observations of one stimulus together. Compare against position/area and center or top-left baselines, then test on a held-out UI family. Report discrimination, calibration, uncertainty intervals clustered by participant and screen, detector error, and failures by task/device/language. A sparse multi-bin lookup table is likely unstable; start with a small regularized or hierarchical model and publish support counts. Only show a numeric estimate on a new page if out-of-domain performance and calibration are acceptable.

## Possible report contract after validation

Each model result would carry `prediction_type` (free-viewing or task-cued search), `model_version`, `training_dataset_versions`, `rights_status`, `task_cue`, `viewing_window_ms`, `viewport`, `element_box`, `element_class`, `detector_confidence`, `prediction`, `uncertainty`, `calibration_summary`, and `out_of_domain` status. Label screenshot pins as **predictions**, distinct from measured gaze and from S2C reviewer callouts. Suppress per-element probabilities when a task, UI family, or language falls outside validation coverage; retain the existing qualitative audit.

The [AGD component loss weights](https://arxiv.org/html/2407.02439v1) are optimization settings, not empirical attention multipliers. Published heatmap figures cannot recover ordered fixations. [WIC640](https://link.springer.com/article/10.1186/s40708-025-00274-x) describes raw fixation-coordinate records, whereas a later paper describes the *released WebSaliency assets* as fixation and saliency maps without raw coordinates. Verify the artifact format for each corpus rather than assigning both to a “maps only” bucket.
