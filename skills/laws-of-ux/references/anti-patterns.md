# Anti-patterns

Do not ship these.

| Mistake | What to do instead |
|---|---|
| All 19 laws on one screen | One primary law per issue. Group overlaps. |
| "Cut the menu and conversion rises 40%" | State the mechanism. Delete the number unless the user supplied it. |
| Fitts for a label, Hick for a tiny button | Swap them. Size and distance are [motor principles](motor.md). Count and equivalence are [decision principles](decision.md). |
| Miller as "never more than 7 items" | Chunk. The quota is the myth. |
| Jakob as "never invent anything" | Convention is the default. Novelty must pay for relearning, not be banned. |
| Postel as "accept invalid data and store it raw" | Accept predictable formats, normalize, display clean. Reject impossible values. |
| Tesler as "add a tooltip so the complexity is handled" | A tooltip does not absorb a step. A default or a derivation does. |
| Von Restorff on every card | One isolated item. Emphasis is a scarce resource. |
| Doherty as "the page must load in 400 ms" | 400 ms is the feel of a single interaction, not a document-load budget. |
| Peak-end as "make the illustration prettier" | The peak and the ending are moments in the flow, usually the error and the confirmation. |
| Poster wireframe presented as their product | Use the screenshot, or say the plate is neutral. |
| Law cited with no region | Name the control, field, or block. |

Aesthetic-usability is not in the core set. A polished screen can still fail Fitts, Hick, and Postel. Do not let polish close a finding.
