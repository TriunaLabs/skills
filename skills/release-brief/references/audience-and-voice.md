# Audience and voice

| Audience | Emphasize | Usually de-emphasize |
| --- | --- | --- |
| Users | New capability, corrected behavior, required action, known limitations | Internal refactors, test-only changes |
| Developers | APIs, schemas, migration steps, deprecations, dependencies, implementation constraints | Marketing language |
| Operators | Deployment prerequisites, configuration, migrations, monitoring, rollback, incidents | Internal UI polish without operational effect |
| Executives | Outcome, scope, adoption risk, material limitations, readiness | Commit-level mechanics |

Use direct language. Separate observed change from expected benefit. Preserve product terminology from supplied evidence, avoid invented feature names, and label the document `draft` until publication is explicitly approved.
